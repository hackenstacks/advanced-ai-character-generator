● MCP = Model Context Protocol

  A standardized way for AI applications to connect to external tools/data
  sources without rebuilding integrations.

  The flow:
  Claude (or any AI) ←→ MCP Server ←→ External Tool/Service
                                      (file system, Slack, GitHub, Brave Search,
  etc.)

  What it does:
  1. Resources — Read files, docs, APIs without hardcoding paths
  2. Tools — Call functions (search, fetch, analyze) with structured input
  3. Prompts — Pre-built system instructions that guide the AI

  Real example:
  Character asks: "Search for information about space"
    ↓
  MCP calls Brave Search tool
    ↓
  Returns results to character
    ↓
  Character continues conversation with new knowledge

  Why it matters:
  - No hardcoded API keys or endpoints
  - Swappable tools (Brave → Google → local search)
  - Dynamic — add/remove tools without code changes
  - Secure — keys stay server-side

  In character creator context:
  - Character could call MCP tools during chat (Brave Search, file lookup, etc.)
  - Or MCP provides knowledge that gets injected into character's memory
  - Or MCP server itself acts as an LLM provider

  Clear enough?

  // services/mcp/mcp-server.ts
  import * as fs from 'fs';
  import * as tls from 'tls';

  const MCP_PORT = 9000;
  const CERT_PATH = process.env.MCP_CERT_PATH || '~/.config/nexus/mcp/';

  export function startMCPServer() {
    const server = tls.createServer({
      key: fs.readFileSync(`${CERT_PATH}/server.key`),
      cert: fs.readFileSync(`${CERT_PATH}/server.crt`),
      requestCert: true,  // mutual TLS
      rejectUnauthorized: false,
    }, (socket) => {
      // Verify client cert OR API key
      verifyClientAuth(socket);

      // Listen for MCP requests (JSON-RPC over socket)
      socket.on('data', async (data) => {
        const request = JSON.parse(data);
        const response = await routeMCPCall(request);
        socket.write(JSON.stringify(response));
      });
    });

    server.listen(MCP_PORT, () => {
      console.log(`[MCP] Server listening on :${MCP_PORT} (TLS + mutual auth)`);
    });
  }

  async function routeMCPCall(request) {
    const { method, params } = request;

    switch(method) {
      case 'character/invoke':
        return await invokeCharacter(params.name, params.prompt,
  params.context);

      case 'search/web':
        return await searchWeb(params.query);

      case 'search/local':
        return await searchLocal(params.query);

      case 'bridge/ask_aichat':
        return await askAichat(params.prompt, params.character_context);

      default:
        return { error: 'Unknown method' };
    }
  }

  Now — memory algorithms + long-term memory toggles. Let me lay out the

  Memory Algorithm Options

  ┌────────────────────────────────────────────────────────────┐
  │  1. SLIDING WINDOW   — last N messages. Cheap, forgets fast │
  │  2. ROLLING SUMMARY  — compress old turns → running summary │
  │     (framework already has summaryApiConfig for this)       │
  │  3. RAG / VECTOR      — embed msgs, retrieve by similarity   │
  │     (framework already has ragEnabled + embeddingConfig)    │
  │  4. IMPORTANCE-WEIGHTED (Generative Agents / Stanford)      │
  │     score = importance × recency-decay × relevance          │
  │  5. HIERARCHICAL (MemGPT/Letta) — working+recall+archival,  │
  │     character self-edits its own memory                     │
  └────────────────────────────────────────────────────────────┘

  My recommendation — a hybrid, tiered to match the char dir standard:

  Working memory   → last N turns          (in-context, always)
  Episodic         → rolling summary        (summaryApiConfig, exists)
  Semantic/recall  → RAG vector store       (embeddingConfig, exists)
  Importance gate  → score × recency decay  (what to promote to long-term)
     ↓ persist (encrypted, per char dir standard)
  $VAULT/characters/<slug>/memory/  (AES-256-GCM, one password)

  The importance score decides what graduates from a chat into permanent recall
  — so the character remembers what mattered, not everything.
